# Sheebase Board — прототип совместной онлайн-доски

Рабочий прототип «бесконечной» доски для совместной визуальной работы по образцу Miro: стикеры, фигуры, коннекторы, фреймы, рисование и редактирование в реальном времени несколькими участниками.

- Технические требования, анализ референса и архитектура: [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md)

## Быстрый старт

Требуется Node.js ≥ 20.

```bash
npm install
npm run build
npm start
```

Откройте http://localhost:3000. Чтобы проверить совместную работу, откройте ту же доску во втором окне или на другом устройстве в той же сети. Ссылку копирует кнопка «Поделиться».

Режим разработки: Vite с горячей перезагрузкой на http://localhost:5173, запросы `/api` и `/ws` проксируются на сервер :3000.

```bash
npm run dev
```

## Полная опись функционала

### 1. Дашборд досок

Стартовая страница (`#/`).

| Функция | Как работает |
|---|---|
| Создание доски | Карточки шаблонов: «Пустая доска», «Ретроспектива», «Канбан», «Брейншторм», «Майнд-мэп». Клик создаёт доску и сразу открывает её. Имя по умолчанию — название шаблона или «Новая доска» |
| Список досок | Все доски сервера, сортировка по дате изменения (новые сверху). Карточка показывает название, дату («сегодня, 14:05» или «12 нояб. 2026 г.») и число объектов с русским склонением |
| Поиск | Фильтр по подстроке в названии, без учёта регистра |
| Переименование | Меню «⋯» → «Переименовать»: поле прямо в карточке, Enter или потеря фокуса — сохранить, Esc — отменить |
| Дублирование | Меню «⋯» → «Дублировать»: копия всех объектов, имя «<название> (копия)» |
| Удаление | Меню «⋯» → «Удалить» с подтверждением. Участники, у которых доска открыта, видят сообщение «Доска удалена» |
| Профиль | В шапке: аватар, поле имени, выбор из 10 цветов (см. [раздел 14](#14-профиль-участника)) |
| Ошибки | Если сервер недоступен, показывается «Сервер недоступен. Проверьте, что он запущен.» |

### 2. Холст и навигация

| Функция | Как работает |
|---|---|
| Бесконечный холст | Координаты без ограничений (валидация до ±10 000 000). Точечная сетка с шагом 24 единицы движется и масштабируется вместе с видом, при масштабе меньше 30% скрывается |
| Масштаб | 10–400%. Ctrl/⌘ + колесо и pinch на тачпаде — к точке под курсором. Кнопки «−»/«+» (шаг ×1,25), клавиши `+`/`-`, Ctrl/⌘ + `=`/`-`. Клик по проценту — 100% |
| Pinch на сенсорном экране | Два пальца одновременно масштабируют и сдвигают вид |
| Панорамирование | Колесо или тачпад (Shift + колесо — по горизонтали), Пробел + перетаскивание, средняя кнопка мыши, инструмент «Рука» (H) |
| Вписать всё | Shift+1 или кнопка ⛶ — весь контент в окне, масштаб не больше 100% |
| Масштаб 100% | Shift+0 или Ctrl/⌘+0 |
| К выделению | Shift+2 — выделенные объекты в окне, масштаб не больше 200% |
| Мини-карта | 200×130 px в правом нижнем углу: объекты цветом (стикеры — своим, фреймы — контуром) и рамка видимой области. Клик или перетаскивание переносят вид. Скрывается кнопкой с иконкой карты, на узких экранах (< 720 px) не показывается |
| Память вида | Положение и масштаб сохраняются для каждой доски в браузере. При первом открытии вид вписывается в содержимое |
| Курсор | Зависит от инструмента: стрелка, «рука», «кулак» при панорамировании, перекрестье для создания, круг ластика |

### 3. Инструменты

Левая вертикальная панель. После создания объекта инструмент возвращается к «Выбору», кроме пера и ластика.

| Инструмент | Клавиша | Поведение | Доп. настройки (панель справа) |
|---|---|---|---|
| Выбор | V | Выделение, перемещение, изменение размера | — |
| Рука | H | Перетаскивание сдвигает вид | — |
| Стикер | N | Клик ставит стикер 200×200 центром в точку клика и открывает ввод текста | 10 цветов |
| Текст | T | Клик создаёт текстовый блок и открывает ввод | — |
| Фигуры | S (R — прямоугольник, O — эллипс) | Клик — фигура 200×200, протягивание — фигура нужного размера (Shift — квадрат/круг). Сразу открывается ввод текста | 8 видов фигур |
| Коннектор | L | Протягивание от объекта к объекту (или в пустое место). Целевой объект подсвечивается | Прямая / ломаная / кривая |
| Перо | P | Свободное рисование со сглаживанием | 14 цветов, толщина 2/4/8/14 |
| Ластик | E | Удаляет штрихи пера, которых касается (круг-курсор) | — |
| Фрейм | F | Клик — фрейм 800×600, протягивание — своего размера. Имя «Фрейм N» | — |
| Изображение | — | Выбор файла с диска | — |
| Отменить / Повторить | Ctrl+Z / Ctrl+Shift+Z | Кнопки внизу панели | — |

### 4. Объекты и их свойства

| Тип | Свойства | Особенности |
|---|---|---|
| **Стикер** | Цвет (10: жёлтый, оранжевый, красный, розовый, фиолетовый, синий, голубой, зелёный, салатовый, серый), текст | 200×200. Размер шрифта подбирается автоматически: максимальный, при котором текст помещается, причём целые слова не разрываются (посимвольный перенос — только если иначе не помещается). Тень. Изменение размера — только пропорциональное |
| **Фигура** | Вид (прямоугольник, скруглённый, эллипс, треугольник, ромб, параллелограмм, шестиугольник, звезда), заливка (16 цветов, включая «без заливки»), цвет и толщина обводки (1–8), текст, размер и цвет текста | Текст центрируется во «вписанной» области фигуры и уменьшается, если не помещается. 8 маркеров размера |
| **Текст** | Текст, размер шрифта (10–120), цвет, жирный, выравнивание (лево/центр/право) | Ширина 320 по умолчанию, высота подстраивается под содержимое. Боковые маркеры меняют ширину (перенос строк), угловые масштабируют шрифт. Пустой блок удаляется после завершения ввода |
| **Коннектор** | Стиль (прямой, ломаный ортогональный, кривой), цвет, толщина (1–8), стрелка в начале и в конце, подпись (до 500 символов) | Каждый конец либо привязан к объекту (сторона выбирается автоматически — та, что обращена к другому концу), либо свободен. Привязанный конец следует за объектом. Концы выделенного коннектора можно перетаскивать и переподключать. Удаляется вместе с объектом, к которому привязан |
| **Штрих пера** | Цвет, толщина | Точки упрощаются (Рамер — Дуглас — Пекер) и сглаживаются. Масштабируется как объект |
| **Фрейм** | Заголовок (до 500 символов), заливка | Всегда рисуется под остальными объектами. Заголовок над левым верхним углом, постоянного экранного размера. Перемещение фрейма переносит всё, что целиком лежит внутри: вложенные фреймы, коннекторы, заблокированные объекты |
| **Изображение** | — | PNG, JPEG, GIF, WebP, SVG. Загрузка кнопкой, вставка из буфера, перетаскивание файлов (до 10 за раз). Картинки больше 1600 px уменьшаются (кроме GIF и SVG). На доске — не больше 480 единиц по большей стороне. Изменение размера — пропорциональное |

Порядок отрисовки: фреймы → остальные объекты по слою (`z`) → коннекторы.

### 5. Выделение и манипуляции

| Функция | Как работает |
|---|---|
| Выделение кликом | Клик по объекту. Shift+клик добавляет или убирает. Клик по пустому месту снимает выделение |
| Выделение рамкой | Протягивание по пустому месту (и по пустой области фрейма). Выделяются пересечённые рамкой объекты, фреймы — только целиком попавшие |
| Выделение фрейма | Клик по заголовку или по пустой области фрейма (без протягивания) |
| Выделить всё | Ctrl/⌘+A. Esc снимает выделение |
| Перемещение | Перетаскивание (порог 4 px) или стрелки: 1 единица, с Shift — 10. Фрейм переносит своё содержимое и при перетаскивании, и стрелками. Свободные концы выделенных коннекторов сдвигаются вместе с выделением |
| Умные направляющие | При перетаскивании края и центры выделения притягиваются (порог 6 px) к краям и центрам видимых объектов, рисуются розовые линии. Alt — без привязки |
| Изменение размера | Маркеры: стикер и изображение — 4 угловых (пропорционально); текст — 4 угловых (масштаб шрифта) и 2 боковых (ширина); фигура, фрейм и штрих — 8 (Shift — пропорционально). Несколько объектов — 4 угловых, пропорциональное масштабирование всей группы |
| Быстрое создание «+» | У одиночного выделенного стикера, фигуры, текста или изображения по сторонам есть кнопки «+». Клик создаёт копию того же вида с пустым текстом (у изображения — стикер) в 100 единицах в эту сторону, обходя занятые места, соединяет кривой стрелкой и открывает ввод. Перетаскивание от «+» проводит коннектор |
| Новый стикер двойным кликом | Двойной клик по пустому месту холста или фрейма |
| Удаление | Delete или Backspace. Заблокированные объекты не удаляются (с подсказкой). Привязанные коннекторы удаляются вместе с объектом |
| Слои | PageUp — на передний план, PageDown — на задний (сохраняется порядок внутри выделения) |
| Группировка | Ctrl/⌘+G — группа, Ctrl/⌘+Shift+G — разгруппировать. Клик по любому участнику выделяет всю группу. При копировании группа копируется как новая группа |
| Блокировка | Ctrl/⌘+Shift+L. Заблокированный объект выделяется (пунктирная серая рамка), но не двигается, не меняет размер, не редактируется и не удаляется. Внутри фрейма переезжает вместе с фреймом |
| Отмена жеста | Esc во время перетаскивания, изменения размера, рисования коннектора или работы ластиком возвращает всё как было. Так же откатывается жест, прерванный браузером (pointercancel) |

### 6. Контекстная панель

Плавающая панель над выделением (или под ним, если сверху нет места). Скрывается во время перетаскивания.

| Выделение | Элементы |
|---|---|
| Любое | Цвет (для стикеров — палитра стикеров, для остальных — общая палитра), Дублировать, На передний план, На задний план, Сгруппировать (2+ объекта) или Разгруппировать, Заблокировать, Удалить |
| Фигура | Вид фигуры, цвет обводки, толщина обводки, размер шрифта (−/+), цвет текста |
| Текст | Размер шрифта (−/+), жирный, выравнивание (3 варианта) |
| Коннектор | Толщина, стиль линии (3 варианта), стрелка в начале, стрелка в конце |
| Штрих пера | Толщина |
| Только заблокированные | Одна кнопка «Разблокировать» |

При смешанном выделении показываются только общие элементы, цвет применяется к «основному цвету» каждого объекта: у фигуры — к заливке, у линии — к обводке. Нажатия на панель не забирают фокус у редактируемого текста.

### 7. Редактирование текста

| Функция | Как работает |
|---|---|
| Начать | Двойной клик или Enter по выделенному объекту. Новый стикер, текст и фигура сразу открываются для ввода |
| Что редактируется | Стикер, фигура, текст — содержимое; коннектор — подпись; фрейм — заголовок (поле ввода) |
| Завершить | Esc, Ctrl/⌘+Enter или клик вне объекта |
| Вставка | Только простой текст, форматирование отбрасывается |
| Синхронизация | Текст уходит участникам по мере ввода |
| Лимиты | Текст — 20 000 символов, подпись и заголовок — 500. При достижении предела ввод обрезается и показывается подсказка |
| История | Создание объекта и ввод текста — один шаг отмены. Брошенный пустой текстовый блок не оставляет следа в истории |

### 8. Буфер обмена и дублирование

| Функция | Как работает |
|---|---|
| Копировать / вырезать | Ctrl/⌘+C / X. В системный буфер кладётся JSON (`sheebase/items`) с выделенными объектами, содержимым выделенных фреймов и коннекторами между ними |
| Вставить | Ctrl/⌘+V: объекты Sheebase вставляются с новыми идентификаторами центром в позицию курсора (работает между вкладками и досками); изображение из буфера — как объект «изображение»; простой текст — как стикер (до 5000 символов) |
| Дублировать | Ctrl/⌘+D — копия со сдвигом на 30 единиц |
| Переподключение коннекторов | Коннекторы между копируемыми объектами привязываются к копиям, концы, привязанные к объектам вне копии, становятся свободными |

### 9. История действий

| Функция | Как работает |
|---|---|
| Отмена и повтор | Ctrl/⌘+Z, Ctrl/⌘+Shift+Z или Ctrl/⌘+Y, кнопки на панели. Глубина — 300 шагов |
| Что считается шагом | Одно перетаскивание, изменение размера, рисование коннектора, проход ластиком, сессия ввода текста вместе с созданием объекта, любая команда (удалить, вставить, группировать и т. д.) |
| Чьи действия | Только свои. Отмена отправляется остальным участникам как обычное изменение |
| Выделение | Восстанавливается выделение на момент шага |

### 10. Совместная работа

| Функция | Как работает |
|---|---|
| Синхронизация в реальном времени | Изменения (включая промежуточные состояния перетаскивания и ввод текста) пакетируются по 30 мс и рассылаются всем участникам доски |
| Курсоры | Курсоры участников с именем и цветом, до 25 обновлений в секунду, плавное движение |
| Выделения участников | Объекты, выделенные другими, обводятся их цветом с подписью имени |
| Присутствие | Аватары участников в шапке (до 6 и счётчик «+N»). Клик по аватару переносит вид к курсору участника |
| Статус соединения | Иконка: онлайн, подключение, офлайн (клик — переподключиться сейчас), ошибка |
| Конфликты | Last-Writer-Wins на уровне отдельных полей в порядке сервера: одновременное изменение разных полей одного объекта (например, цвет и позиция) сохраняет оба изменения. Клиенты гарантированно сходятся к состоянию сервера |
| Работа без сети | Правки продолжают работать локально и отправляются после переподключения (повтор через 0,5 → 1 → 2 → … → 10 с). Переименование без сети тоже не теряется |
| Коррекция | Если сервер отбросил часть данных при валидации, автор получает актуальное состояние этих объектов |
| Поделиться | Кнопка копирует ссылку на доску. Доступ — у всех, у кого есть ссылка |
| Переименование доски | Клик по названию в шапке. Новое имя сразу видно всем |

### 11. Хранение данных

| Функция | Как работает |
|---|---|
| Формат | Каждая доска — файл `DATA_DIR/boards/<id>.json` со структурой `{meta, items}` |
| Автосохранение | Отложенная запись через 300 мс после изменения |
| Надёжность | Атомарная запись (временный файл + rename). Повреждённые файлы пропускаются при загрузке, объекты повторно проверяются валидатором. При SIGINT/SIGTERM несохранённое записывается на диск |
| Идентификаторы | Случайные, 12 символов base62 (≈71 бит) |

### 12. Экспорт и импорт

Меню ⤓ в шапке. Если что-то выделено, экспортируется выделение (с содержимым выделенных фреймов), иначе вся доска.

| Формат | Как работает |
|---|---|
| PNG | Растр с плотностью 2× на белом фоне. Крупные доски автоматически ограничиваются по размеру холста браузера |
| SVG | Вектор: фигуры, текст (с переносами как на доске), коннекторы со стрелками и подписями, изображения |
| JSON | Бэкап `sheebase/board` со всеми объектами |
| Импорт JSON | Объекты из бэкапа (или из буфера) добавляются с новыми идентификаторами в центр экрана. Отменяется одним Ctrl+Z |

### 17. Протокол WebSocket

Путь `/ws`, сообщения — JSON. Первое сообщение клиента — `hello`.

| Направление | Сообщение | Назначение |
|---|---|---|
| C→S | `{t:'hello', boardId, user:{id,name,color}}` | Вход на доску |
| C→S | `{t:'ops', seq, ops:[…]}` | Пакет операций `add` / `update` / `delete` |
| C→S | `{t:'cursor', x, y}` | Позиция курсора (`null` — ушёл с холста) |
| C→S | `{t:'selection', ids}` | Своё выделение |
| C→S | `{t:'rename', name}` | Переименование доски |
| S→C | `{t:'init', meta, items, peers, clientId}` | Снимок доски |
| S→C | `{t:'ack', seq}` | Пакет применён |
| S→C | `{t:'ops', from, ops}` | Операции других участников (или коррекция от `server`) |
| S→C | `{t:'join', peer}` / `{t:'leave', clientId}` | Присутствие |
| S→C | `{t:'cursor', from, x, y}` / `{t:'selection', from, ids}` | Курсоры и выделения |
| S→C | `{t:'meta', meta}` | Метаданные доски |
| S→C | `{t:'error', code, message}` | `not_found`, `deleted`, `bad_request` |

Соединения проверяются ping/pong каждые 30 с.

### 20. Тестирование

- `npm test` (Vitest): операции и их сжатие, геометрия, содержимое фреймов, валидация и отчёт о коррекции, история undo/redo и транзакции, клонирование, умные направляющие, регрессии найденных багов, рандомизированный тест сходимости синхронизации (300 сценариев), REST API, WebSocket-комнаты, коррекция отправителя, сохранение между перезапусками.

## Архитектура

```
src/
  shared/      модель данных, операции (applyOps), геометрия, валидация, шаблоны — общие для клиента и сервера
  server/      Express (REST + статика), ws (WebSocket-комнаты), файловое хранилище досок
  client/
    pages/     дашборд
    board/     холст, взаимодействия, оверлей, панели, контроллер (история + синхронизация), экспорт
tests/         Vitest
e2e/           Playwright-сценарий
docs/          технические требования
```

**Синхронизация.** Клиент применяет свои изменения сразу (оптимистично), пакетирует их (~30 мс) и отправляет на сервер с порядковым номером. Сервер применяет пакеты строго в порядке поступления, рассылает их остальным и подтверждает отправителю. Пока изменение поля не подтверждено, клиент игнорирует чужие изменения этого поля: сервер всё равно применит наше позже. Так все клиенты сходятся к состоянию сервера, а одновременные изменения разных полей одного объекта не теряются. Подробнее — раздел 7 требований.

**Рендеринг.** Объекты — DOM-элементы и SVG внутри контейнера с CSS-трансформацией камеры. При движении перерисовываются только изменённые объекты. Рамки выделения, маркеры и курсоры рисуются в экранных координатах поверх холста. Раскладка текста считается через `canvas.measureText` — одинаково для отображения и экспорта.

## Ограничения прототипа

Нет аутентификации и прав доступа (доступ по ссылке), комментариев, голосования, таймера, истории версий, поворота объектов, таблиц и карточек. Сервер — один процесс с файловым хранилищем. Изображения хранятся внутри JSON доски. Полный список — раздел 8 требований.

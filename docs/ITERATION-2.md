## 1. Как искались пробелы

Прототип v0.1 закрывает «механику» доски: объекты, редактирование, синхронизацию. Пробелы искались по трём направлениям:

1. **Сценарии из требований (UC-1…UC-7), пройденные целиком.** Где пользователь вынужден выйти из продукта или сделать работу вручную?
2. **Сравнение с Miro** по функциям, которые чаще всего используются на реальных сессиях (фасилитация, навигация по большим доскам, асинхронная работа).
3. **Риски для данных и удобства**, видимые по устройству кода: например, отсутствие защиты от ошибочного массового изменения.

### 1.1 Найденные пробелы в сценариях

| Сценарий | Что не получается сейчас | Чем закрыть |
|---|---|---|
| Ретроспектива (UC-1) | Команда собрала стикеры, но приоритизировать их нечем: голосование ведут в чате или считают точки вручную | **Голосование** с лимитом голосов и скрытыми до конца итогами |
| Воркшоп с таймбоксами | Ведущий засекает время на телефоне, участники его не видят | **Общий таймер** |
| Ведение сессии | Ведущий не может показать всем нужное место доски, участники теряются на большой доске | **Следование за участником** и **«Собрать всех ко мне»** |
| Демонстрация результатов | Фреймы есть, но показать их по порядку можно только ручным зумом | **Панель фреймов и режим презентации** |
| Асинхронная работа | Обсудить объект можно только текстом на самой доске, что засоряет её | **Комментарии** (треды, ответы, «решено», непрочитанные) |
| Большая доска (сотни объектов) | Найти стикер по тексту невозможно | **Поиск по доске** (Ctrl+F) |
| Аккуратная схема | Выравнивать объекты приходится «на глаз», направляющие помогают только по одному | **Выравнивание и распределение** |
| Привычные жесты | Правый клик ничего не делает, все действия — только через панель и клавиши | **Контекстное меню** |
| Новая активность на существующей доске | Шаблон можно выбрать только при создании доски | **Вставка шаблона в открытую доску** |
| Ошибка или вандализм | Случайное удаление половины доски «по чужим ctrl+z» не откатить: undo отменяет только свои действия | **История версий** со снимками и восстановлением |
| Выбор доски на дашборде | Карточки одинаковые, доски различаются только названием | **Миниатюры досок** |
| Ссылки на материалы | URL можно вписать только текстом, перейти по нему нельзя | **Ссылки на объектах** |
| Ретро с обсуждением | Неизвестно, кто написал стикер | **Автор стикера** (по желанию — показывать) |
| Одновременный ввод | Два человека, правящие один стикер, затирают друг друга, не видя этого | **Индикатор «редактирует …»** и защита от одновременного ввода |
| Смена имени | Новое имя видно коллегам только после переподключения | **Обновление профиля на лету** |

## 2. Общая инфраструктура

Функции F1–F4, F10, F14, F15 требуют общих расширений. Они проектируются один раз.

### 2.1 Два вида данных доски

| Вид | Что относится | Модель согласования |
|---|---|---|
| **Объекты** (`items`) | Стикеры, фигуры и т. д., а также новые поля `link`, `author` | Как в v0.1: оптимистичные операции, LWW по полям, `pending`/`ack`, undo/redo |
| **Сессионные данные** (новое) | Таймер, голосование, комментарии | **Сервер-авторитетная модель**: клиент отправляет *намерение* («проголосовать за X», «ответить в тред»), сервер проверяет права и лимиты, применяет и рассылает результат. Не участвуют в undo/redo |

Сессионные данные выделены в отдельную модель по двум причинам:
- **Счётчики и списки, которые пополняют несколько людей одновременно** (голоса, ответы в треде), при LWW по полю теряли бы данные. На сервере они применяются как атомарные операции в порядке поступления, конфликтов нет.
- **Ограничения, которые нельзя проверить на клиенте** (не больше N голосов на человека, автор сообщения — тот, кто его отправил), проверяет сервер.

Задержка таких действий — один RTT (десятки миллисекунд). Для голоса, комментария и кнопок таймера это незаметно.

### 2.2 Хранение

Файл доски дополняется (старые файлы без новых полей читаются со значениями по умолчанию):

```ts
interface StoredBoard {
  meta: BoardMeta;
  items: ItemMap;
  comments: Record<string, CommentThread>; // F1
  session: { timer: TimerState | null; voting: VotingState | null }; // F2, F3
}
```

Версии (F10) лежат отдельно: `DATA_DIR/versions/<boardId>/index.json` + `<versionId>.json`.

### 2.3 Расширение протокола WebSocket

| Направление | Сообщение | Функция |
|---|---|---|
| S→C | `init` + поля `comments`, `session`, `now`; у `peers` — `view`, `selection`, `editing` | все |
| C→S | `selection {ids, editing}` (добавлено `editing`) | F14 |
| C→S / S→C | `user {name, color}` / `peer {peer}` | F15 |
| C→S / S→C | `view {rect}` / `view {from, rect}` | F4 |
| C→S / S→C | `summon` / `summon {from}` | F4 |
| C→S | `timer {action, durationMs?, deltaMs?}` | F3 |
| C→S | `voting {action, votesPerUser?}`, `vote {itemId, delta}` | F2 |
| S→C | `session {session, now}` — индивидуально каждому (свои голоса) | F2, F3 |
| C→S | `comment {action, …}` | F1 |
| S→C | `thread {thread}` / `thread-delete {id}` | F1 |
| S→C | `reset {items, reason}` | F10 |

**Часы.** Сервер добавляет `now` (своё время) в `init` и `session`. Клиент хранит смещение `offset = now − Date.now()` и считает остаток таймера по серверным часам: `endsAt − (Date.now() + offset)`. Погрешность — половина RTT, для таймера достаточно.

### 2.4 Присутствие

Сервер хранит для каждого подключения последние `view`, `selection`, `editing` и отдаёт их в `init`. Без этого новый участник не мог бы сразу начать «следовать» за коллегой, который не двигал вид, и не видел бы, что кто-то уже редактирует объект.

## 3. Технический дизайн функций

### F1. Комментарии

**Модель:**
```ts
interface CommentMessage { id: string; authorId: string; authorName: string; authorColor: string; text: string; createdAt: number }
interface CommentThread {
  id: string;
  x: number; y: number;          // абсолютная позиция (для свободного комментария или если объект удалён)
  itemId: string | null;         // объект, к которому привязан тред
  dx: number; dy: number;        // смещение от левого верхнего угла объекта
  resolved: boolean;
  createdAt: number; updatedAt: number;
  messages: CommentMessage[];    // первое сообщение — открывает тред
}
```
Позиция пина: `item ? (item.x + dx, item.y + dy) : (x, y)`. Пин «едет» вместе с объектом без отдельных обновлений.

**Протокол** (`C→S {t:'comment', action, …}`):

| action | Поля | Проверки сервера |
|---|---|---|
| `create` | `x, y, itemId?, text` | текст 1–2000 символов, координаты, объект существует |
| `reply` | `threadId, text` | тред существует |
| `resolve` | `threadId, resolved` | — |
| `deleteMessage` | `threadId, messageId` | только своё сообщение; удаление первого сообщения удаляет тред |
| `delete` | `threadId` | — |

Автор (`id`, имя, цвет) берётся сервером из подключения, а не из сообщения, поэтому подделать автора нельзя. Время ставит сервер. Ответ рассылается всем: `thread {thread}` или `thread-delete {id}`.

**Удаление объекта.** Когда в пакете операций есть `delete` объекта с тредами, сервер переводит их в «свободные»: записывает текущую абсолютную позицию, обнуляет `itemId` и рассылает обновлённые треды. То же делается после восстановления версии.

**Клиент:**
- Инструмент «Комментарий» (клавиша **C**): клик по объекту или холсту открывает черновик с полем ввода. Enter отправляет, Shift+Enter — перенос строки, Esc — отмена.
- Пины рисуются в экранном слое оверлея (постоянный размер при любом масштабе): аватар автора, число ответов, точка «непрочитано». Решённые скрыты, пока не включено «Показывать решённые».
- Клик по пину открывает карточку треда: сообщения (автор, относительное время, текст), поле ответа, «Решить / Открыть снова», удаление своих сообщений, удаление треда.
- Панель комментариев (кнопка в шапке со счётчиком открытых тредов): фильтр «Открытые / Решённые», клик переносит вид к пину и открывает тред.
- **Непрочитанные**: время последнего просмотра треда хранится в `localStorage` (`sheebase:seen:<boardId>`). Тред непрочитан, если `updatedAt` новее, а последнее сообщение не своё.

**Почему не объекты доски.** Комментарии не должны попадать в экспорт, выделение, мини-карту, «вписать всё», undo/redo. Хранение отдельно избавляет от исключений в десятке мест.

**Тесты:** сервер — создание, ответ, решение, удаление своих и чужих сообщений, отказ на пустой и длинный текст, перевод треда в свободный при удалении объекта, сохранение на диск. E2E — комментарий одного участника виден другому, ответ, «решено».

### F2. Голосование

**Модель на сервере:**
```ts
interface VotingState {
  id: string; status: 'active' | 'ended';
  votesPerUser: number;            // 1–99
  startedBy: string; startedAt: number; endedAt: number | null;
  votes: Record<userId, Record<itemId, number>>;
}
```
**Что видит клиент** (сервер формирует индивидуально):
```ts
interface VotingView {
  id; status; votesPerUser; startedBy; startedAt; endedAt;
  myVotes: Record<itemId, number>;      // только свои
  voters: number;                       // сколько участников уже голосовало
  results: Record<itemId, number> | null; // итоги — только после завершения
}
```
Чужие голоса до конца сессии не уходят клиентам вообще. Это и честность голосования (участник не подстраивается под других), и анонимность на уровне протокола.

**Протокол:**
- `voting {action: 'start', votesPerUser}`, `voting {action: 'end'}`, `voting {action: 'clear'}`.
- `vote {itemId, delta: 1 | -1}`. Сервер проверяет: голосование активно; объект существует и голосуемый (стикер, фигура, текст, изображение); для `+1` — не исчерпан лимит пользователя; для `−1` — есть свой голос за объект.
- После каждого изменения сервер рассылает `session` каждому участнику — со своими `myVotes`.

Ключ — `userId` профиля, а не подключение: две вкладки одного человека делят одни голоса.

**Клиент:**
- Кнопка «Голосование» в шапке: выбор числа голосов (1–10) и «Начать»; во время сессии — «Завершить»; после — итоги и «Очистить».
- **Режим голосования**, пока сессия активна: клик по голосуемому объекту — голос, Alt+клик — снять. Перетаскивание по холсту сдвигает вид, редактирование и инструменты недоступны (как в Miro: во время голосования доска «заморожена»).
- Баннер: «Осталось X из N голосов», «проголосовали: K», «Завершить».
- Бейджи на объектах: во время голосования — свои голоса, после — итог.
- Панель итогов: объекты по убыванию голосов с текстом, клик — к объекту.

**Тесты:** сервер — лимит голосов, снятие, голос за несуществующий объект, скрытие чужих голосов до конца, итоги после завершения, общий лимит у двух вкладок одного пользователя.

### F3. Таймер

**Модель:**
```ts
interface TimerState { durationMs: number; endsAt: number | null; remainingMs: number; running: boolean; by: string }
```

| Действие | Эффект на сервере |
|---|---|
| `start {durationMs}` (5 с – 3 ч) | `running`, `endsAt = now + duration` |
| `pause` | `remainingMs = endsAt − now`, `running = false` |
| `resume` | `endsAt = now + remainingMs` |
| `add {deltaMs}` (±1 ч) | сдвиг `endsAt` (или `remainingMs` на паузе), не меньше нуля |
| `reset` | таймер удалён |

Сервер не держит интервалов: истечение вычисляется по `endsAt`. Клиенты обновляют отображение 4 раза в секунду по серверным часам (см. 2.3). На нуле у всех одновременно показывается «Время вышло», пилюля таймера мигает, звучит короткий сигнал (Web Audio, без файлов).

**Клиент:** кнопка-пилюля в шапке (`мм:сс` во время работы), меню: пресеты 1/3/5/10/15 мин и своё значение, «Пауза/Продолжить», «+1 мин», «Сброс».

**Тесты:** сервер — старт, пауза, продолжение, добавление времени, границы длительности, сохранение в файле.

### F4. Следование за участником и «Собрать всех ко мне»

- Клиент сообщает свою видимую область в мировых координатах: `view {x, y, w, h}` не чаще раза в 150 мс при изменении камеры или размера окна. Сервер хранит последнюю и рассылает остальным.
- **Следование:** меню аватара участника → «Следовать». Пока режим включён, при каждом `view` ведущего камера вписывает его область (центр совпадает, масштаб — по меньшей стороне). Режим выключается при любом собственном движении камеры (колесо, перетаскивание, кнопки зума, мини-карта), по Esc и при уходе ведущего. Вид обводится рамкой цвета ведущего с плашкой «Вы следуете за … · Перестать».
- **«Собрать всех ко мне»**: меню своего аватара → `summon`. Сервер рассылает `summon {from}`, у остальных включается следование за вызвавшим.
- Различение «своего» и «чужого» движения камеры: `setCamera(cam, source)`, где `source = 'follow'` у программных перемещений следования. Любой другой источник отключает следование.

**Тесты:** e2e — после `summon` камера второго участника совпадает с областью первого и меняется вместе с ней. Колесо мыши отключает следование.

### F5. Поиск по доске

- Ctrl/⌘+F открывает строку поиска (перехватывается только на странице доски).
- Ищется подстрока в тексте стикеров, фигур, текстовых блоков, подписях коннекторов и заголовках фреймов. Без учёта регистра, «ё» = «е».
- Результаты упорядочены «как читают»: сверху вниз, слева направо.
- Enter / Shift+Enter (или кнопки ↑↓) — следующий / предыдущий результат, вид центрируется на нём (масштаб поднимается до 100%, если объект слишком мелкий). Все совпадения подсвечиваются в оверлее, текущее — ярче. Счётчик «3 из 12».
- Чистая клиентская функция `searchItems(items, query)` покрывается юнит-тестами.

### F6. Панель фреймов и режим презентации

- **Порядок фреймов**: «как читают» — по строкам (фреймы с пересекающимися по вертикали областями считаются одной строкой), внутри строки — слева направо. Функция `frameOrder(items)` тестируется отдельно.
- **Панель** (кнопка в левой панели): список с номером, названием и числом объектов. Клик — вписать фрейм и выделить его.
- **Презентация**: кнопка в панели. Интерфейс скрывается, окно переходит в полноэкранный режим (если браузер разрешает), камера вписывает текущий фрейм.
  - Навигация: →, ↓, PageDown, Пробел — вперёд; ←, ↑, PageUp — назад; Home/End.
  - Нижняя плашка: «◀ 2 / 5 ▶», «Собрать всех» (участники начинают следовать за докладчиком, F4), «Выход». Esc тоже выходит.
  - Редактирование в режиме презентации отключено.

### F7. Выравнивание и распределение

- В контекстной панели при выделении 2+ объектов — меню «Выровнять»: по левому краю, по центру, по правому краю, по верху, по середине, по низу. Для 3+ объектов — «Распределить по горизонтали / вертикали».
- Горячие клавиши: Alt+A / Alt+D / Alt+W / Alt+S — лево / право / верх / низ, Alt+H / Alt+V — центр по горизонтали / вертикали, Alt+Shift+H / Alt+Shift+V — распределить.
- **Алгоритм выравнивания**: опорная линия берётся из общей рамки выделения (min/max/центр), каждому объекту вычисляется сдвиг `(dx, dy)`.
- **Алгоритм распределения**: объекты сортируются по центру, крайние остаются на месте. Промежуток = (общая длина − сумма размеров) / (n − 1), объекты расставляются последовательно.
- Сдвиги применяются через тот же механизм, что и перемещение: фрейм переносит содержимое, заблокированные объекты и коннекторы не двигаются. Одна операция — один шаг undo.
- Чистые функции `alignDeltas` / `distributeDeltas` тестируются отдельно.

### F8. Контекстное меню

- Правый клик (или долгое нажатие на сенсорном экране) по объекту выделяет его, если он не выделен, и открывает меню у курсора.
- **По выделению:** Копировать, Вырезать, Вставить, Дублировать, Удалить; На передний / задний план; Группировать / Разгруппировать; Заблокировать / Разблокировать; Выровнять (2+); Добавить комментарий; Экспорт выделения в PNG.
- **По пустому месту:** Вставить, Добавить стикер здесь, Добавить комментарий здесь, Выделить всё, Вписать всё.
- **Буфер обмена из меню:** запись через `navigator.clipboard.writeText` плюс внутренняя копия последнего скопированного. Вставка — через `navigator.clipboard.readText`, при отказе браузера — из внутренней копии.
- Меню закрывается по клику вне, Esc, колесу мыши.

### F9. Вставка шаблона в открытую доску

- Кнопка «Шаблоны» в левой панели: список шаблонов, клик вставляет выбранный в центр экрана.
- Объекты шаблона строятся той же функцией `buildTemplate`, что и на сервере, затем клонируются с новыми идентификаторами и `z` поверх существующих. Вид вписывается во вставленное, вставка — один шаг undo.

### F10. История версий

**Сервер:** модуль `VersionStore`: `DATA_DIR/versions/<boardId>/index.json` (метаданные) + `<versionId>.json` (объекты). Запись атомарная.

**Когда создаются снимки:**
- **Автоматически** — перед применением изменений, если с последнего снимка прошло ≥ 10 минут, а доска менялась. Снимок фиксирует состояние *до* новой серии правок. Первый снимок делается при первом изменении доски.
- **Вручную** — «Сохранить версию» с названием.
- **Перед восстановлением** — «Перед восстановлением «…»», поэтому восстановление тоже можно откатить.
- **Хранение:** не больше 50 автоматических (старые удаляются) и 100 ручных версий.

**REST:**

| Метод и путь | Назначение |
|---|---|
| `GET /api/boards/:id/versions` | Список версий (новые сверху) |
| `POST /api/boards/:id/versions` `{name}` | Сохранить текущее состояние |
| `GET /api/boards/:id/versions/:vid` | Версия с объектами (для предпросмотра) |
| `POST /api/boards/:id/versions/:vid/restore` | Восстановить |
| `DELETE /api/boards/:id/versions/:vid` | Удалить версию |

**Восстановление:**
1. Снимок текущего состояния.
2. Объекты версии повторно проходят валидацию и заменяют объекты доски.
3. Треды, привязанные к исчезнувшим объектам, становятся свободными.
4. Всем участникам уходит `reset {items, reason}`.

Клиент обрабатывает `reset` как `init`: свежий снимок плюс повторно применённые неподтверждённые пакеты (они уже в пути и сервер применит их после восстановления). История undo/redo очищается, потому что ссылается на прежнее состояние.

**Клиент:** панель «История версий» (кнопка в шапке): список с названием, временем, числом объектов и пометкой «авто»; «Сохранить версию»; клик по версии — предпросмотр (SVG тем же экспортёром, что и для экспорта), «Восстановить» (с подтверждением), «Удалить».

**Тесты:** сервер — авто-снимок по интервалу (время подменяется), ручной снимок, восстановление (рассылка `reset`, снимок «перед восстановлением», освобождение тредов), лимит авто-версий, удаление версий вместе с доской.

### F11. Миниатюры досок

- Общая чистая функция `renderThumbnailSvg(items)` в `shared/thumbnail.ts`: фреймы, стикеры (цветом), фигуры (их контуром), строки текста (полосками), изображения (плашкой), штрихи и коннекторы. Без измерения текста, поэтому работает на сервере.
- `GET /api/boards/:id/thumbnail.svg` с `ETag = updatedAt` (ответ `304`, если не менялась) и заголовком `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'`. Все значения атрибутов экранируются.
- **Защита в глубину:** валидатор начинает проверять цвета по шаблону (`#rgb[a]`, `#rrggbb[aa]`, `transparent`, имя цвета, `rgb()/rgba()`), чтобы в SVG не попала разметка.
- Дашборд показывает миниатюру в карточке (`loading="lazy"`), пустая доска — первая буква названия.

### F12. Ссылки на объектах

- Новое поле `link: string | null` у стикера, фигуры, текста, изображения и фрейма. Валидация: `http://` или `https://`, до 2000 символов, без пробелов и управляющих символов.
- В контекстной панели одиночного объекта — кнопка «Ссылка»: поле URL, «Сохранить», «Открыть», «Удалить».
- На объекте — значок-ссылка в правом верхнем углу (постоянного экранного размера). Клик открывает адрес в новой вкладке с `noopener,noreferrer` и не выделяет объект.

### F13. Автор стикера

- Новое поле `author: string | null` (имя на момент создания) у стикеров, созданных на доске (инструмент, двойной клик, «+», вставка текста). Копии сохраняют автора оригинала, у шаблонов автора нет.
- Настройка вида «Показывать авторов стикеров» (меню «Вид» в шапке, хранится в браузере). Если включена, внизу стикера выводится имя автора, а область для текста уменьшается, чтобы подпись не перекрывала его.

### F14. Индикатор редактирования

- В `selection` добавлено поле `editing`. У объекта, который редактирует другой участник, показывается плашка «✎ Имя».
- Попытка начать ввод в таком объекте отклоняется с подсказкой «Сейчас редактирует Анна». Одновременный старт ввода (в пределах RTT) остаётся возможен: тогда работает обычный LWW.

### F15. Обновление профиля на лету

- При смене имени или цвета клиент отправляет `user {name, color}`. Сервер обновляет данные подключения и рассылает `peer {peer}`: курсоры, аватары и выделения у коллег обновляются сразу.

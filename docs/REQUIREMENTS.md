---

## 1. Общие сведения

### 1.1 Назначение
Прототип — веб-приложение «бесконечной» онлайн-доски для совместной визуальной работы: брейншторминги, ретроспективы, канбан, схемы процессов, майнд-мэпы. Несколько участников одновременно работают на одной доске и видят изменения друг друга в реальном времени.

### 1.2 Цели прототипа
1. Воспроизвести ядро пользовательского опыта Miro: бесконечный холст, стикеры, фигуры, коннекторы, фреймы, рисование, совместное редактирование.
2. Проверить архитектуру синхронизации (сервер-авторитетная модель с оптимистичными локальными изменениями).
3. Получить работающую основу, которую можно развивать до MVP (аутентификация, права, комментарии и т. д. — вне рамок, см. раздел 8).

### 1.3 Приоритеты требований
Используется нотация MoSCoW:
- **M (Must)** — обязательно для прототипа;
- **S (Should)** — важно, реализуется в прототипе;
- **C (Could)** — желательно, при наличии времени;
- **W (Won't)** — осознанно не входит в прототип.

## 2. Анализ референса: как устроен Miro

Miro организован вокруг нескольких ключевых концепций. Ниже — как каждая работает в Miro и какое решение принято для прототипа.

| Концепция | Как это работает в Miro | Решение для прототипа |
|---|---|---|
| Рабочее пространство и доски | Дашборд со списком досок, поиск, создание доски с нуля или из шаблона | **Да**: дашборд, поиск, CRUD досок, 4 шаблона |
| Бесконечный холст | Холст без границ, масштаб от ~1% до 400%, точечная сетка, мини-карта, «вписать всё» | **Да**: масштаб 10–400%, сетка, мини-карта, «вписать всё» |
| Навигация | Колесо/тачпад, пробел+перетаскивание, средняя кнопка мыши, инструмент «Рука», pinch-zoom | **Да** |
| Левая панель инструментов | Выбор, стикеры, текст, фигуры, коннекторы, перо, фреймы, загрузка, шаблоны | **Да** (без шаблонов внутри доски) |
| Стикеры | Квадратные заметки нескольких цветов, текст автоматически уменьшается под размер | **Да** |
| Фигуры | Библиотека базовых и блок-схемных фигур, текст внутри, заливка/обводка | **Да**: 8 фигур |
| Текст | Свободный текстовый блок, стили шрифта | **Да** |
| Коннекторы | Прямые/ломаные/кривые линии, «прилипают» к объектам и следуют за ними, стрелки, подписи | **Да** |
| Перо и ластик | Свободное рисование, маркер, ластик | **Да** (перо + ластик) |
| Фреймы | Именованные области; содержимое перемещается вместе с фреймом; используются как «слайды» | **Да** (без режима презентации) |
| Изображения, файлы, встраивания | Загрузка картинок, PDF, видео, embed-ссылок | **Частично**: только изображения |
| Контекстная панель | Плавающая панель над выделением со свойствами объекта | **Да** |
| Быстрое создание связанных объектов | Кнопки «+» по сторонам фигуры/стикера: клик — копия с коннектором | **Да** |
| Выравнивание | Умные направляющие, привязка к краям и центрам | **Да** (при перемещении) |
| Группировка и блокировка | Группы объектов, блокировка от изменений | **Да** |
| Совместная работа | Курсоры участников с именами, аватары присутствия, мгновенная синхронизация | **Да** |
| Комментарии, @упоминания, реакции | Комментарии к объектам и областям | **W** |
| Фасилитация | Голосование, таймер, «следовать за ведущим», видеозвонок, Talktrack | **W** |
| Права доступа | Команды, роли (владелец/редактор/комментатор/наблюдатель), приглашения | **W** — доступ по ссылке |
| История | Undo/redo, история версий доски | **Частично**: undo/redo |
| Экспорт | PNG, PDF, CSV, бэкап доски | **Частично**: PNG, SVG, JSON-бэкап + импорт |
| Таблицы, карточки, Kanban-виджет, документы | Структурированные виджеты | **W** (канбан — через шаблон из фреймов и стикеров) |
| Miro AI | Генерация стикеров, кластеризация, саммари | **W** |
| Интеграции, Marketplace, REST API/SDK | Jira, Slack, Google Drive, публичный API | **W** (только внутренний REST API) |

Вывод: для прототипа критичны (1) холст и навигация, (2) базовые объекты и их редактирование, (3) мгновенная синхронизация между участниками с корректным разрешением конфликтов, (4) надёжное сохранение.

## 3. Глоссарий

| Термин | Определение |
|---|---|
| Доска | Документ с набором объектов на бесконечном холсте; имеет уникальную ссылку |
| Объект (item) | Элемент доски: стикер, фигура, текст, коннектор, штрих пера, фрейм, изображение |
| Мировые координаты | Координаты холста, не зависящие от масштаба и сдвига вида |
| Камера (вид) | Сдвиг и масштаб, с которыми пользователь смотрит на холст |
| Операция (op) | Атомарное изменение доски: `add` (добавить объект), `update` (изменить поля), `delete` (удалить) |
| Пир (peer) | Другой участник, подключённый к той же доске |
| LWW | Last-Writer-Wins — побеждает запись, последней обработанная сервером |

## 4. Пользователи и сценарии

Роль одна — **участник** (без регистрации; имя и цвет задаются локально).

| ID | Сценарий |
|---|---|
| UC-1 | Участник создаёт доску из шаблона «Ретроспектива», копирует ссылку и отправляет команде |
| UC-2 | Несколько участников одновременно добавляют стикеры, двигают их, видят курсоры друг друга |
| UC-3 | Участник рисует блок-схему: фигуры + коннекторы, которые следуют за фигурами при перемещении |
| UC-4 | Участник строит майнд-мэп кнопками быстрого создания «+» |
| UC-5 | Участник группирует идеи во фреймы и переносит фреймы вместе с содержимым |
| UC-6 | Участник экспортирует результат в PNG и делает JSON-бэкап |
| UC-7 | У участника пропадает сеть: он продолжает работать, после восстановления связи изменения доходят до остальных |

## 5. Функциональные требования

### 5.1 Дашборд досок (FR-DASH)

| ID | Пр. | Требование |
|---|---|---|
| FR-DASH-01 | M | Список досок: название, дата изменения, количество объектов; сортировка по дате изменения (новые сверху) |
| FR-DASH-02 | M | Создание доски: пустой или из шаблона — «Ретроспектива», «Канбан», «Брейншторм», «Майнд-мэп» |
| FR-DASH-03 | M | Переименование, дублирование и удаление доски (удаление — с подтверждением) |
| FR-DASH-04 | S | Поиск досок по названию |
| FR-DASH-05 | M | Имя и цвет пользователя хранятся локально в браузере, редактируются без регистрации |

### 5.2 Холст и навигация (FR-CNV)

| ID | Пр. | Требование |
|---|---|---|
| FR-CNV-01 | M | Бесконечный холст с точечной сеткой, сетка масштабируется и сдвигается вместе с видом |
| FR-CNV-02 | M | Масштаб 10%–400%: Ctrl/⌘ + колесо и pinch на тачпаде (зум к точке под курсором), кнопки «−»/«+», клавиши `+`/`-`; pinch двумя пальцами на тач-экране |
| FR-CNV-03 | M | Панорамирование: колесо/тачпад (Shift — по горизонтали), пробел + перетаскивание, средняя кнопка мыши, инструмент «Рука» (H) |
| FR-CNV-04 | M | «Вписать всё» (Shift+1), «Масштаб 100%» (Shift+0), «К выделению» (Shift+2) |
| FR-CNV-05 | S | Мини-карта: все объекты и рамка видимой области; клик и перетаскивание перемещают вид; скрывается кнопкой |
| FR-CNV-06 | S | Положение и масштаб вида запоминаются для каждой доски локально; при первом открытии вид вписывается в содержимое |

### 5.3 Объекты (FR-OBJ)

| ID | Пр. | Требование |
|---|---|---|
| FR-OBJ-01 | M | **Стикер**: квадрат 200×200 (мировых единиц), 10 цветов; размер шрифта подбирается автоматически, чтобы текст поместился; изменение размера — пропорциональное |
| FR-OBJ-02 | M | **Фигура**: прямоугольник, скруглённый прямоугольник, эллипс, треугольник, ромб, параллелограмм, шестиугольник, звезда. Свойства: тип, заливка (в т. ч. прозрачная), цвет и толщина обводки, текст внутри, размер и цвет текста |
| FR-OBJ-03 | M | **Текст**: блок с переносом строк по ширине; размер шрифта 10–120, цвет, жирный, выравнивание (лево/центр/право); высота блока подстраивается под содержимое |
| FR-OBJ-04 | M | **Коннектор**: стиль — прямой, ломаный (ортогональный), кривой; каждый конец либо привязан к объекту (и следует за ним при перемещении), либо свободен; стрелка на каждом конце вкл/выкл; цвет, толщина; текстовая подпись посередине |
| FR-OBJ-05 | M | **Перо**: свободное рисование со сглаживанием, выбор цвета и толщины; инструмент остаётся активным после штриха. **Ластик**: удаляет штрихи, которых касается |
| FR-OBJ-06 | M | **Фрейм**: прямоугольная область с заголовком и заливкой; рисуется под остальными объектами; при перемещении фрейма перемещаются объекты, целиком лежащие внутри него |
| FR-OBJ-07 | S | **Изображение**: загрузка с диска, вставка из буфера обмена, перетаскивание файла на холст; изображения больше 1600 px уменьшаются на клиенте; изменение размера — пропорциональное |
| FR-OBJ-08 | M | После создания объекта (кроме пера и ластика) инструмент возвращается в режим «Выбор»; новый стикер, текст и фигура сразу переходят в режим ввода текста |

### 5.4 Выделение и редактирование (FR-SEL)

| ID | Пр. | Требование |
|---|---|---|
| FR-SEL-01 | M | Выделение кликом; Shift+клик — добавить/убрать из выделения; рамкой (протягиванием по пустому месту, в т. ч. внутри фрейма); Ctrl/⌘+A — всё. Фрейм выделяется кликом по заголовку или по пустой области фрейма |
| FR-SEL-02 | M | Перемещение перетаскиванием и стрелками (1 ед., Shift — 10 ед.) |
| FR-SEL-03 | M | Изменение размера за маркеры (8 маркеров у фигур/фреймов/штрихов, 4 угловых у стикеров/изображений, боковые + угловые у текста); Shift — сохранить пропорции; групповое масштабирование нескольких объектов |
| FR-SEL-04 | S | Умные направляющие при перемещении: привязка к краям и центрам соседних объектов с отрисовкой линий; Alt — временно отключить |
| FR-SEL-05 | M | Удаление (Delete/Backspace); коннекторы, привязанные к удаляемым объектам, удаляются вместе с ними |
| FR-SEL-06 | M | Дублирование (Ctrl+D); копирование/вырезание/вставка (Ctrl+C/X/V) через системный буфер — работает между вкладками и досками; вставка простого текста создаёт стикер, вставка картинки — изображение. Коннекторы при копировании переподключаются к копиям |
| FR-SEL-07 | M | Порядок слоёв: «На передний план» (PageUp), «На задний план» (PageDown) |
| FR-SEL-08 | S | Блокировка (Ctrl+Shift+L): заблокированный объект нельзя переместить, изменить или удалить; его можно выделить и разблокировать |
| FR-SEL-09 | S | Группировка (Ctrl+G) и разгруппировка (Ctrl+Shift+G): клик по объекту группы выделяет всю группу |
| FR-SEL-10 | M | Редактирование текста: двойной клик или Enter по выделенному объекту; Esc или клик вне — завершить; вставка в редактор — только простой текст |
| FR-SEL-11 | M | Контекстная панель над выделением: набор свойств зависит от типа объектов (цвет, фигура, обводка, шрифт, стиль линии, стрелки), общие действия — слои, блокировка, дублирование, удаление |
| FR-SEL-12 | S | Быстрое создание: у выделенного стикера/фигуры/текста/изображения по сторонам отображаются кнопки «+». Клик — создать такой же объект в этом направлении и соединить коннектором; перетаскивание — провести коннектор к любому объекту или в пустое место |

### 5.5 История действий (FR-HIST)

| ID | Пр. | Требование |
|---|---|---|
| FR-HIST-01 | M | Undo (Ctrl+Z) / Redo (Ctrl+Shift+Z, Ctrl+Y) не менее 200 шагов; кнопки в интерфейсе |
| FR-HIST-02 | M | Отменяются только собственные действия пользователя; одно перетаскивание, одно изменение размера или одна сессия ввода текста — один шаг |
| FR-HIST-03 | M | Отмена/повтор синхронизируются с другими участниками как обычные изменения |

### 5.6 Совместная работа (FR-COL)

| ID | Пр. | Требование |
|---|---|---|
| FR-COL-01 | M | Изменения (включая промежуточные состояния при перетаскивании, изменении размера и вводе текста) видны другим участникам с задержкой не более 200 мс в локальной сети |
| FR-COL-02 | M | Курсоры других участников с именем и цветом, плавное движение |
| FR-COL-03 | M | Аватары участников, находящихся на доске, в шапке; индикатор состояния соединения |
| FR-COL-04 | S | Подсветка объектов, выделенных другими участниками, их цветом |
| FR-COL-05 | M | Разрешение конфликтов на уровне отдельных полей объекта по правилу LWW (порядок задаёт сервер). Одновременное изменение разных полей одного объекта не теряет ни одно из изменений. Все клиенты сходятся к состоянию сервера |
| FR-COL-06 | M | При потере соединения — индикация, автоматическое переподключение с экспоненциальной задержкой; изменения, сделанные без связи, отправляются после восстановления |
| FR-COL-07 | M | Доступ по ссылке: кнопка «Поделиться» копирует URL доски |
| FR-COL-08 | M | Переименование и удаление доски сразу отражаются у всех участников |

### 5.7 Хранение (FR-STO)

| ID | Пр. | Требование |
|---|---|---|
| FR-STO-01 | M | Сервер хранит состояние всех досок и автоматически сохраняет его на диск не позднее 1 с после изменения; данные переживают перезапуск сервера |
| FR-STO-02 | M | Запись атомарная (временный файл + переименование), повреждённые файлы не мешают загрузке остальных досок |
| FR-STO-03 | M | При остановке сервера (SIGINT/SIGTERM) несохранённые изменения записываются на диск |

### 5.8 Экспорт и импорт (FR-EXP)

| ID | Пр. | Требование |
|---|---|---|
| FR-EXP-01 | M | Экспорт в PNG (2× плотность) всей доски или только выделенных объектов |
| FR-EXP-02 | S | Экспорт в SVG |
| FR-EXP-03 | S | Экспорт доски в JSON (бэкап) и импорт JSON на текущую доску (объекты получают новые идентификаторы, импорт отменяется одним Undo) |

### 5.9 Горячие клавиши (FR-KEY)

| Действие | Клавиши |
|---|---|
| Выбор / Рука | V / H |
| Стикер / Текст / Фигура / Коннектор / Перо / Ластик / Фрейм | N / T / S (R — прямоугольник, O — эллипс) / L / P / E / F |
| Временная «рука» | удерживать Пробел |
| Отменить / Повторить | Ctrl+Z / Ctrl+Shift+Z, Ctrl+Y |
| Выделить всё / Снять выделение | Ctrl+A / Esc |
| Удалить / Дублировать | Delete, Backspace / Ctrl+D |
| Копировать / Вырезать / Вставить | Ctrl+C / Ctrl+X / Ctrl+V |
| Группировать / Разгруппировать / Блокировать | Ctrl+G / Ctrl+Shift+G / Ctrl+Shift+L |
| Передний / задний план | PageUp / PageDown |
| Масштаб: +/−, вписать всё, 100%, к выделению | `+` / `-`, Shift+1, Shift+0, Shift+2 |
| Редактировать текст | Enter или двойной клик |
| Справка по клавишам | `?` |

(На macOS вместо Ctrl используется ⌘.)

## 6. Нефункциональные требования

| ID | Категория | Требование |
|---|---|---|
| NFR-01 | Производительность | Плавное (≈60 fps) панорамирование, масштабирование и перетаскивание на доске из 500 объектов на типовом ноутбуке; при движении перерисовываются только изменённые объекты |
| NFR-02 | Производительность | Трафик при перетаскивании ограничен пакетированием операций (не чаще ~30 пакетов/с), курсоры — не чаще 25 сообщений/с |
| NFR-03 | Совместимость | Актуальные версии Chrome, Edge, Firefox, Safari (десктоп); базовая поддержка сенсорного ввода |
| NFR-04 | Надёжность | Сервер валидирует все входящие сообщения и операции (типы, размеры, числовые значения); некорректные данные отбрасываются без падения процесса; максимальный размер сообщения — 20 МБ |
| NFR-05 | Надёжность | Детект «мёртвых» соединений (ping/pong каждые 30 с) |
| NFR-06 | Безопасность | Аутентификации нет (прототип). Идентификаторы досок случайные (≥ 60 бит энтропии). Пользовательский текст выводится только как текст (без HTML) — защита от XSS |
| NFR-07 | Локализация | Интерфейс на русском языке |
| NFR-08 | Развёртывание | Node.js ≥ 20; запуск одной командой; без внешней БД (файловое хранилище); порт задаётся переменной `PORT`, каталог данных — `DATA_DIR` |

## 7. Архитектура

### 7.1 Компоненты

```
┌──────────────────────── Браузер (React SPA) ───────────────────────┐
│ Дашборд ── REST ──┐                                                 │
│ Доска: Canvas (DOM+SVG), Overlay, Toolbar, ContextToolbar, Minimap  │
│          │ состояние: zustand-store (items, selection, camera…)     │
│          │ Controller: транзакции, история undo/redo                │
│          │ SyncEngine: пакетирование, pending-поля, ack, ресинк     │
└──────────┼──────────────────────┼───────────────────────────────────┘
           │ WebSocket /ws        │ HTTP /api
┌──────────┴──────────────────────┴────── Node.js сервер ─────────────┐
│ Rooms: комнаты по доскам, рассылка ops/курсоров/присутствия         │
│ BoardRepository: состояние досок в памяти + отложенная запись       │
│ shared: типы, applyOps, валидация, геометрия, шаблоны               │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ data/boards/<id>.json
```

### 7.2 Стек
- **Клиент**: TypeScript, React 19, zustand (состояние), Vite (сборка), lucide-react (иконки). Рендеринг холста — DOM-элементы и SVG внутри контейнера с CSS-трансформацией камеры; служебные элементы (рамки выделения, маркеры, курсоры) — в экранных координатах поверх холста.
- **Сервер**: Node.js, Express 5 (REST и статика), ws (WebSocket), tsx (запуск TypeScript).
- **Тесты**: Vitest (юнит и интеграция), Playwright (e2e).

### 7.3 Модель данных
Все объекты имеют общие поля: `id`, `type`, `x`, `y`, `w`, `h` (рамка в мировых координатах), `z` (порядок слоя), `locked`, `groupId`.

| Тип | Специфичные поля |
|---|---|
| `sticky` | `text`, `color` |
| `shape` | `shape` (rect, roundrect, ellipse, triangle, diamond, parallelogram, hexagon, star), `fill`, `stroke`, `strokeWidth`, `text`, `fontSize`, `textColor` |
| `text` | `text`, `fontSize`, `color`, `bold`, `align` |
| `frame` | `title`, `fill` |
| `image` | `src` (data URL) |
| `path` | `points` (плоский массив координат относительно `x`,`y`), `stroke`, `strokeWidth` |
| `connector` | `from`, `to` (конечные точки: `itemId?`, `side` = auto/top/right/bottom/left, `x`, `y`), `lineStyle` (straight/elbow/curved), `startArrow`, `endArrow`, `stroke`, `strokeWidth`, `label` |

Метаданные доски: `id`, `name`, `createdAt`, `updatedAt`, `itemCount`.

Слои отрисовки: фреймы → прочие объекты (по `z`) → коннекторы.

### 7.4 Операции
```ts
type Op =
  | { t: 'add';    item: Item }                  // добавить или заменить объект
  | { t: 'update'; id: string; patch: Partial }  // изменить отдельные поля
  | { t: 'delete'; id: string };                 // удалить
```
Применение операций (`applyOps`) — общая чистая функция для клиента и сервера.

### 7.5 Протокол WebSocket (`/ws`, JSON)

| Направление | Сообщение | Назначение |
|---|---|---|
| C→S | `hello {boardId, user}` | Подключение к доске |
| C→S | `ops {seq, ops[]}` | Пакет локальных операций с порядковым номером |
| C→S | `cursor {x, y}` / `selection {ids}` / `rename {name}` | Курсор, выделение, переименование |
| S→C | `init {meta, items, peers, clientId}` | Снимок доски и список участников |
| S→C | `ack {seq}` | Подтверждение применения пакета отправителя |
| S→C | `ops {from, ops[]}` | Операции других участников |
| S→C | `join` / `leave` / `cursor` / `selection` / `meta` / `error` | Присутствие, курсоры, метаданные, ошибки |

### 7.6 Алгоритм согласования изменений
1. Клиент применяет свои операции локально сразу (оптимистично), копит их в пакет (~30 мс) и отправляет с номером `seq`.
2. При локальной операции клиент помечает затронутые ключи как ожидающие (`pending`): поле — `id.field`, объект целиком — `id` (для add/delete).
3. Сервер применяет пакеты строго в порядке поступления, рассылает их остальным и отвечает отправителю `ack {seq}`.
4. Входящие чужие операции применяются, кроме полей, по которым у клиента есть неподтверждённые изменения (сервер всё равно применит их позже и они «победят»).
5. По `ack` снимаются отметки `pending`, относящиеся к этому `seq`.
6. При переподключении клиент получает свежий снимок, повторно применяет к нему все неподтверждённые пакеты и отправляет их заново.

Результат: все клиенты сходятся к состоянию сервера, разные поля одного объекта сливаются без потерь (FR-COL-05).

### 7.7 REST API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/health` | Проверка работоспособности |
| GET | `/api/templates` | Список шаблонов |
| GET | `/api/boards` | Список досок |
| POST | `/api/boards` | Создать доску `{name?, template?}` |
| GET | `/api/boards/:id` | Метаданные и объекты доски |
| PATCH | `/api/boards/:id` | Переименовать `{name}` |
| POST | `/api/boards/:id/duplicate` | Дублировать доску |
| DELETE | `/api/boards/:id` | Удалить доску |

### 7.8 Хранилище
Каждая доска — файл `DATA_DIR/boards/<id>.json` (`{meta, items}`). Все доски загружаются в память при старте; запись — отложенная (debounce 300 мс), атомарная.

## 9. Критерии приёмки

| ID | Проверка |
|---|---|
| AC-01 | Создать доску из шаблона «Ретроспектива» на дашборде → открывается доска с тремя фреймами и стикерами |
| AC-02 | Два окна браузера на одной доске: стикер, созданный в первом, появляется во втором; перемещение видно во время перетаскивания; курсор первого участника виден во втором с именем |
| AC-03 | Соединить две фигуры коннектором, переместить одну — коннектор следует за ней у обоих участников |
| AC-04 | Ввести текст в стикер: шрифт уменьшается по мере заполнения, текст не выходит за границы |
| AC-05 | Переместить фрейм — объекты внутри перемещаются вместе с ним |
| AC-06 | Ctrl+Z отменяет перемещение одним шагом; Ctrl+Shift+Z — повторяет; изменения видны второму участнику |
| AC-07 | Перезапустить сервер — доска и все объекты сохранились |
| AC-08 | Отключить сеть, переместить объект, включить сеть — второй участник видит изменение |
| AC-09 | Экспорт PNG скачивает изображение с содержимым доски |
| AC-10 | Одновременное изменение цвета (участник A) и позиции (участник B) одного стикера — оба изменения сохраняются у обоих |
| AC-11 | Отправка некорректного JSON / операций в WebSocket не роняет сервер |
| AC-12 | `npm test` и `npm run e2e` проходят |

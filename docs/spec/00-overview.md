# Обзор, границы, роли, правила работы

> Извлечено из `docs/SPEC.md` (разд. 1–3, 15.5, 15.8, 15.9). Источник истины — SPEC.md; этот файл не редактируется вручную, идентификаторы требований сохранены.

## 1. Контекст и цели

### 1.1. Продукт

Облачная веб-платформа для студенческих проектных команд. Документы, интерактивная доска и задачи хранятся в одном рабочем пространстве и связаны между собой в граф знаний. ИИ-модуль превращает загруженные материалы (конспекты, статьи, ТЗ, протоколы) в интеллект-карту на доске и черновики задач. Семантический поиск отвечает на вопросы со ссылками на источники. Совместное редактирование построено на CRDT (Yjs).

### 1.2. Технологическое ядро (собственная разработка, основа для регистрации программы для ЭВМ)

1. **Модуль ИИ-автоструктурирования**: сегментация → извлечение понятий, связей и действий через LLM → нормализация и объединение понятий → построение иерархии → раскладка интеллект-карты → запись на доску и создание черновиков задач.
2. **Модуль семантического поиска**: гибридный поиск (вектор + полнотекст с русской морфологией), учёт прав доступа, ответы через RAG со ссылками.
3. **Механизм совместного редактирования**: единая модель данных документов и доски на Yjs, собственный движок доски, синхронизация, работа офлайн.

### 1.4. Глоссарий

| Термин | Значение |
|---|---|
| Рабочее пространство (workspace) | Контейнер команды: страницы, задачи, участники, лимиты |
| Страница (page) | Документ или доска, узел дерева страниц |
| Блок (block) | Единица документа BlockNote со стабильным `id` |
| Элемент доски (board item) | Стикер, фигура, текст, связь, узел карты, рамка, изображение |
| Интеллект-карта | Дерево узлов `mindmap_node` на доске, связанное с источниками |
| Черновик задачи | Задача со статусом `draft`, созданная ИИ и ожидающая подтверждения |
| Прогон ИИ (AI run) | Один запуск конвейера автоструктурирования |
| Чанк (chunk) | Фрагмент объекта, проиндексированный для поиска |
| Наблюдатель | Роль `viewer`: руководитель проекта или эксперт, только чтение и сводка |

## 2. Границы MVP

### 2.1. Входит (из заявки)

- регистрация и авторизация, личные и командные пространства, роли владелец / редактор / наблюдатель;
- блочный редактор документов;
- интерактивная доска: стикеры, фигуры, связи, интеллект-карты;
- задачи: канбан, исполнители, сроки, связи с документами и элементами доски;
- модуль ИИ-автоструктурирования;
- модуль семантического поиска и ответов на вопросы;
- импорт DOCX, PDF (с текстовым слоем), Markdown, архивов экспорта Notion (Markdown & CSV);
- гостевой доступ;
- шаблоны для учебных проектов: паспорт проекта, «Стартап как диплом», отчёт по этапу, протокол встречи;
- сводка для наблюдателя;
- лимиты тарифов (без приёма платежей);
- сайт проекта (лендинг) и юридические страницы;
- инструменты для опытной эксплуатации: аналитика, обратная связь, отчёт по пилоту.

### 2.2. Не входит (W)

Базы данных с формулами, диаграммы Ганта, мобильные приложения (веб на мобильном только для чтения, C), интеграция с ЭОС вузов, коробочная версия, приём платежей, OCR сканированных PDF, комментарии и обсуждения в документах, публичные ссылки на страницы для анонимов, SSO, экспорт в DOCX/PDF, пользовательские колонки канбана.

## 3. Пользователи и ключевые сценарии

### 3.1. Роли

| Роль | Кто это | Что может |
|---|---|---|
| Владелец (`owner`) | Создатель пространства, капитан команды | Всё, включая управление участниками, удаление пространства, смену тарифа (через админа) |
| Редактор (`editor`) | Участник команды | Создание и правка страниц, задач, запуск ИИ, импорт |
| Наблюдатель (`viewer`) | Руководитель проекта, преподаватель, эксперт | Чтение всего, поиск и вопросы, сводка по задачам. Не меняет содержимое |
| Гость (`guest`) | Эксперт Фонда или посетитель сайта | Работа в изолированной копии демо-пространства с урезанными лимитами |
| Администратор платформы | Команда проекта | Админ-страница: статистика, отчёт по пилоту, назначение тарифов |

Полная матрица прав — Приложение E.

### 3.2. Сквозные сценарии (каждый — e2e-тест, раздел 12.4)

- **S1. Старт команды.** Регистрация → подтверждение почты → создание командного пространства → приглашение 4 участников и руководителя-наблюдателя по ссылке → участники входят.
- **S2. Автоструктурирование.** Редактор загружает ТЗ (DOCX, 20 страниц) → документ создан → «Структурировать» → в течение 60 с на новой доске появляется интеллект-карта в рамке, а в канбане — колонка «Черновики от ИИ» → редактор принимает 5 черновиков, назначает исполнителей → у задачи видны ссылки на абзацы ТЗ, клик открывает документ с подсветкой блока.
- **S3. Совместная работа.** Пять участников одновременно правят документ и доску, видят курсоры друг друга. Один теряет сеть на 30 с, продолжает править, после восстановления изменения сливаются без потерь.
- **S4. Вопрос к материалам.** Новый участник через месяц спрашивает «Какие требования к интерфейсу?» → получает ответ со ссылками [1]–[n] на блоки ТЗ и протоколов → клик ведёт к источнику.
- **S5. Наблюдатель.** Руководитель открывает сводку: задачи по исполнителям и статусам, просроченные, активность за неделю. Попытка изменить документ невозможна (редактор в режиме чтения).
- **S6. Гость.** Эксперт Фонда на сайте нажимает «Гостевой вход» → попадает в демо-пространство с готовыми документами, картой и задачами → может запустить структурирование демонстрационного файла и задать вопрос.
- **S7. Переезд из Notion.** Пользователь загружает zip экспорта Notion → дерево страниц воссоздано, таблицы баз данных импортированы как таблицы в документах.

### 15.5. Definition of Done для задачи

- [ ] Требования задачи реализованы, ID требований упомянуты в тестах.
- [ ] `pnpm verify` зелёный локально; интеграционные тесты не пропущены (если пропущены — явно сказано).
- [ ] Затронутые e2e зелёные; для UI-задач сделаны скриншоты Playwright ключевых состояний и просмотрены.
- [ ] Права проверяются через `permissions`, есть негативные тесты (403 для ролей без доступа).
- [ ] Все строки интерфейса — в `ru.ts`.
- [ ] Нет `any`, `@ts-ignore`, `eslint-disable` без комментария с причиной.
- [ ] Новые зависимости проходят `licenses:check` и упомянуты в итоге задачи.
- [ ] Миграции сгенерированы drizzle-kit и применяются с нуля (`pnpm db:reset && pnpm db:migrate`).
- [ ] OpenAPI обновлена, если менялось API.
- [ ] `docs/STATUS.md` и `docs/PLAN.md` обновлены.

### 15.8. Запреты

- Выдумывать эталонную разметку, запросы, оценки релевантности, ответы пользователей, результаты испытаний; править числа в `reports/`.
- Ослаблять или удалять тест, чтобы он прошёл, без записи причины в `STATUS.md` и подтверждения человека.
- Вызывать боевые LLM-провайдеры из unit-, int- и e2e-тестов; коммитить ключи и `.env`.
- Добавлять зависимости с запрещёнными лицензиями (14.2) и пакеты `@blocknote/xl-*`, tldraw.
- Использовать сторонние SaaS вне РФ для данных пользователей (аналитика, ошибки, почта, хранилище).
- Скачивать или рисовать логотипы Фонда и Платформы, брать в демо-контент чужие тексты.
- Редактировать применённые миграции, `docs/SPEC.md`, файлы эталонной разметки.

### 15.9. Точки ручного контроля (агент останавливается и спрашивает)

- новая зависимость вне таблицы 6.2 или смена решения из 6.2;
- изменение определения KPI, порогов, состава датасетов оценки;
- изменение промптов после их заморозки для итоговой оценки;
- деструктивные изменения схемы БД (удаление столбцов, таблиц, данных);
- деплой на prod, работа с боевыми данными пилота;
- юридические тексты (политика, согласие, соглашение) — только заготовки с пометкой;
- всё, что увеличивает расходы на облако или ИИ сверх бюджета (смета: облако 110 000 руб., ПО и API 90 000 руб. на проект).

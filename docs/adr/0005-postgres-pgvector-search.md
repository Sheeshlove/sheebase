# ADR 0005. База данных и поиск: PostgreSQL 17 с pgvector

- Статус: принято (решение зафиксировано в docs/SPEC.md, раздел 6.2)
- Дата: 2026-11-12

## Контекст

Нужны реляционные данные, полнотекстовый поиск с русской морфологией и векторный поиск. Бюджет не позволяет держать отдельные сервисы поиска.

## Решение

PostgreSQL 17 с расширением pgvector (образ `pgvector/pgvector:pg17`), встроенная конфигурация FTS `russian`, объединение результатов через RRF. ORM и миграции — Drizzle и drizzle-kit, SQL-миграции коммитятся. Драйвер PostgreSQL — `pg` (решение человека от 2026-11-12). Доступ к БД — только через `packages/db`.

## Альтернативы

- Elasticsearch или OpenSearch: отдельный сервис, память, сопровождение.
- Qdrant или другая векторная БД: второе хранилище и синхронизация с ним.
- Prisma: менее прозрачный SQL и слабее поддержка pgvector.

## Последствия

- Спайк M0.8: на 10 000 чанков гибридный запрос укладывается в 5–7 мс (p95) при цели 700 мс.
- Найдена проблема: HNSW с фильтром по пространству теряет кандидатов (полнота 0,20 при `ef_search = 100`). Запрос из раздела 10.3 нужно уточнить до M8.1 — варианты в `tools/spikes/README.md`, решение за человеком.
- Спайк выполнен на PostgreSQL 16 и pgvector 0.6 (нет Docker); на целевом образе его нужно повторить.

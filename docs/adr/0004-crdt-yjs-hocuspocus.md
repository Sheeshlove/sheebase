# ADR 0004. Совместное редактирование: Yjs и Hocuspocus

- Статус: принято (решение зафиксировано в docs/SPEC.md, раздел 6.2)
- Дата: 2026-11-12

## Контекст

Документы и доски редактируются одновременно несколькими людьми, с работой при обрыве связи и слиянием без конфликтов.

## Решение

CRDT — Yjs (`yjs`, `y-indexeddb`, `y-protocols`). Сервер — Hocuspocus (`@hocuspocus/server`, `extension-database`; `extension-redis` — на случай масштабирования), клиент — `@hocuspocus/provider`. Доступ к Y.Doc в коде — только через `packages/doc-model`.

## Альтернативы

- Automerge: меньше готовых связок с редакторами.
- Собственный протокол операций (как в прототипе первой итерации): пришлось бы самим решать офлайн, слияние и хранение.
- y-websocket: нет аутентификации, хуков хранения и режима только чтения.

## Последствия

- Спайк M0.6 подтвердил работу связки BlockNote + Hocuspocus на двух клиентах.
- Состояние Y.Doc хранится в PostgreSQL, производные данные (поиск, задачи) строятся из него на сервере.
- NFR-PERF-6 (300 соединений на одной ВМ) проверяется нагрузочным тестом в M10.
